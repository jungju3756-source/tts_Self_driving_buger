## 1. 한눈에 보기

```
 [사람] "1번으로 가"
    │  C920 웹캠 마이크 (16 kHz)
    ▼
 ① 말소리 구간 감지 ── voice_ptt.py (로컬, RMS)                      ~0.6 s (말 끝 판정)
    ▼
 ② 받아쓰기 ────────── Gemini gemini-3.5-flash-lite (REST)             ~2 s
    │  "1번으로 가."
    ▼
 ③ 명령 해석 ────────── intent.parse_strict  → ('go', '1번')           <1 ms
    ▼
 ④ 레이블 → 좌표 ───── /places/list (place_manager) → (0.582, -1.806) map 좌표
    ▼
 ⑤ Nav2 목표 전송 ──── navigate_to_pose 액션                          출발 부저
    ▼
 ⑥ 내 위치 추정 ────── AMCL: 라이다 ↔ SLAM 지도 맞추기 → map→odom TF
    ▼
 ⑦ 전역 경로 ──────── planner_server (NavFn) on global costmap, 1초마다 다시 계산
    ▼
 ⑧ 바퀴 속도 ──────── controller_server: RotationShim → DWB (10 Hz)
    ▼
 ⑨ 안전 필터 ──────── velocity_smoother → collision_monitor → /cmd_vel → OpenCR 모터
    ▼
 ⑩ 도착 판정 ──────── goal_checker: 목표 0.15 m 안 (방향은 안 봄)       도착 부저
```

**핵심**: 로봇이 SLAM 지도에서 "1번"이라는 글자를 읽는 것은 아닙니다. **장소 이름 ↔ map 좌표를 저장한 표(`~/maps/places.yaml`)**가 있고, 지도·장소·로봇 위치가 모두 **같은 `map` 좌표계**를 쓰기 때문에 이름만으로 지도 위 위치를 찾아갈 수 있습니다.

## 2. 장소 레이블은 어떻게 만들어지고 지도와 연결되나

### 2-1. SLAM 지도 (한 번만 만듦)
- Cartographer(`rapa1/carto.launch.py`)로 방을 돌며 지도를 만들고, `map_saver`로 저장했습니다.
  - 결과: `~/maps/lab_v2.pgm`(격자 그림), `lab_v2.yaml`(해상도 0.05 m, 원점 (-5.088, -7.795))
- 평소 주행할 때는 이 지도를 `map_server`가 `/map`으로 띄웁니다. 이 지도가 **`map` 좌표계의 기준**이 됩니다.

### 2-2. 장소 저장 (`rapa1/place_manager.py`)
장소는 `map` 좌표 **(x, y[, yaw])**에 이름을 붙여 저장합니다. 저장하는 방법은 세 가지입니다.

| 방법 | 동작 | 좌표 출처 |
|---|---|---|
| 패드 A 1초 누름 | 지금 로봇 위치를 비어 있는 가장 작은 번호("5번")로 저장 | TF `map → base_footprint` (AMCL 이 계산) |
| `tools/place.py here 2번` | 지금 로봇 위치를 그 이름으로 저장 | 위와 같음 (방향 포함) |
| RViz Publish Point → `place.py save 2번` | 지도에서 찍은 점을 저장 | `/clicked_point` (방향 없음) |

- 저장 위치: `~/maps/places.yaml`

  ```yaml
  frame: map
  places:
    1번: {x: 0.582, y: -1.806, yaw: null, aliases: [], saved: '2026-10-02 15:04:36'}
  ```

- 저장하거나 고칠 때마다 다음 두 토픽을 발행합니다. 둘 다 transient-local이라 늦게 켜진 노드도 최신 목록을 바로 받습니다.
  - `/places/list` (JSON 목록)
  - `/places/markers` (RViz·웹 지도에 그리는 이름표)
- 웹 조종석과 RViz의 지도 위 "1번" 글자는 이 마커를 **그린 것**입니다. 지도 파일(pgm) 안에 글자가 들어 있는 게 아닙니다.

### 2-3. 왜 이름만으로 찾아갈 수 있나
```
 lab_v2.pgm (map 좌표계)  ─┬─ places.yaml 의 1번 (0.582, -1.806) 도 map 좌표
                           └─ AMCL 이 로봇 위치를 map 좌표로 계산
```
지도, 장소, 로봇이 같은 좌표계에 있으므로 "1번" → (0.582, -1.806) → Nav2 목표로 바로 이어집니다.

전제는 **AMCL이 로봇 위치를 제대로 잡고 있는 것**입니다. 위치가 틀리면 목표도 장애물도 엉뚱한 곳에 찍힙니다. 오늘 실제로 방향이 15° 틀어져 4번으로 못 간 일이 있었습니다(6장).

## 3. 말 → 장소 이름 (단계 ①~④ 자세히)

### ① 말소리 구간 감지 — `voice_ptt.py` (mode:=listen)
- 마이크를 항상 열어 두고 0.1 초 단위로 소리 크기(RMS)를 잽니다.
- 주변 소음 수준은 계속 따라갑니다.
- **소음 × 3 (최소 400)**보다 큰 소리가 0.3 초 이어지면 말 시작으로 봅니다. 0.6 초 조용하면 말 끝으로 봅니다.
- 0.5 초보다 짧거나 6 초보다 긴 소리는 서버로 보내지 않고 버립니다. 박수, 문소리, 긴 대화 같은 것들입니다.

### ② 받아쓰기 — Gemini
- 잘라낸 구간을 WAV로 만들어 `gemini-3.5-flash-lite`에 보내고 받아쓴 문장만 받습니다.
- 상시 듣기에서는 프롬프트에 장소 이름을 **넣지 않습니다.** 넣으면 잡음을 "1번으로 가"로 지어낼 위험이 있어서입니다.

### ③ 명령 해석 — `web/intent.py` `parse_strict()`
- "멈춰 / 정지 / 그만"은 숫자 없이도 정지합니다.
- 그 밖의 말은 한글 숫자를 아라비아 숫자로 바꿉니다. 예: "일번", "첫 번째" → "1번"
- 그다음 정규식으로 **`N번` + (으로/로/에/까지) + 이동 동사(가/이동/출발/데려/안내)**를 찾습니다.
- 동사 뒤에 올 수 있는 말을 제한해서, 명령이 아닌 말을 걸러냅니다.

| 말 | 결과 |
|---|---|
| "1번으로 가", "3번 이동해", "이 번으로 가줘" | 이동 |
| "1번 어디야", "가자", "1번 가방", "1번으로 가지 마" | 무시 |

- 서로 다른 번호가 둘 이상 나오면 추측하지 않고 무시합니다.
- 주행 중에는 "멈춰"만 받습니다.

### ④ 레이블 → 좌표 — `resolve_place()`
- `/places/list`에서 받은 목록에서 이름이나 별칭이 **정확히 일치**하는 장소를 고릅니다.
- 정확히 일치하는 게 없으면, 서로 포함 관계인 장소가 하나뿐일 때만 그 장소로 인정합니다.
- 등록되지 않은 번호("9번")는 무시합니다.
- 목표 방향은 이렇게 정합니다.
  - 장소에 yaw가 저장돼 있으면 그 방향을 씁니다.
  - 없으면 현재 위치에서 장소를 바라보는 방향을 씁니다.
  - 어느 쪽이든 지금 도착 판정은 방향을 보지 않습니다.

## 4. 좌표 → 도착 (단계 ⑤~⑩, Nav2)

| 단계 | 구성 요소 | 하는 일 | 주요 설정 |
|---|---|---|---|
| ⑤ | `bt_navigator` | 행동 트리(BT) 실행: 경로 계산 → 따라가기 → 실패 시 복구 | `navigate_to_pose_w_replanning_and_recovery.xml`, 서버 대기 **200 ms** |
| ⑥ | `amcl` | 입자 500~2000개로 라이다 점과 지도 벽을 맞춰 위치 추정 | likelihood field, 0.25 m 또는 0.2 rad 움직일 때마다 갱신 |
| ⑦ | `planner_server` (NavFn) | global costmap 위 최소 비용 경로 계산. **1 초마다 다시 계산** | tolerance 0.5 m |
| ⑧ | `controller_server` | **RotationShim**: 경로와 45° 넘게 어긋나면 제자리 회전 → **DWB**: 궤적 819개를 1.5 초 앞까지 시뮬레이션하고 점수가 가장 좋은 속도 선택 | 최고 0.26 m/s, 1.0 rad/s |
| ⑨ | `velocity_smoother` → `collision_monitor` | 가감속을 부드럽게 하고, 2 초 안에 부딪힐 것 같으면 감속하거나 정지 | FootprintApproach 2.0 s |
| ⑩ | `goal_checker` | 목표 **0.15 m** 안이면 도착 | yaw 허용 3.14 (방향 무시) |

- Nav2 노드는 **한 프로세스(`nav2_container`)**로 묶어서 실행합니다 (`localize.launch.py`, composition).
  - 따로 띄우면 노드마다 CPU를 8~18% 써서 BT가 서버 응답을 놓쳤습니다.
  - 묶은 뒤 전체 CPU 사용률이 약 48%에서 30%로 줄었습니다.
  - 되돌리기: `composition:=False`

## 5. 장애물 회피 — 어떻게 피하나

Nav2의 **여러 층**이 같이 동작합니다. 새로 만든 알고리즘은 아니고, Nav2의 구성 요소를 이 로봇에 맞게 설정했습니다.

```
 LDS-02 라이다 (/scan, 바닥에서 13.2 cm 높이, 360°)
    │
    ├─► costmap obstacle/voxel layer ── 라이다에 맞은 칸 = 장애물, 빔이 지나간 칸 = 비움
    │      + static layer (SLAM 지도 벽) + keepout filter (웹에서 그린 가상 벽)
    │      + inflation layer (장애물 둘레 0.5 m 비용, 로봇 반지름 0.22 m 안은 충돌)
    │
    ├─► (1) 전역 경로 다시 계산 1 Hz ── 막히면 비용이 낮은 쪽으로 돌아가는 경로
    ├─► (2) DWB 궤적 평가 10 Hz ─────── 장애물에 닿는 궤적은 버림 (BaseObstacle)
    ├─► (3) collision_monitor ───────── 2 초 앞 충돌 예측 시 감속·정지 (마지막 안전장치)
    └─► (4) 복구 행동 ───────────────── 진행 없음 → costmap 비우기 → 제자리 회전 → 대기 → 후진
```

### 5-1. 층별 설명
1. **비용 지도 (costmap)**
   - global(지도 전체, 1 Hz)과 local(로봇 주변 3 × 3 m, 5 Hz) 두 개가 있습니다.
   - 라이다에 새로 보인 물체가 바로 장애물 칸으로 찍힙니다.
   - 물체를 치우면 빔이 그 칸을 지나가면서 다시 빈칸이 됩니다.
2. **전역 경로 다시 계산**: 1초마다 경로를 새로 계산합니다. 길 위에 장애물이 생기면 그걸 피하는 경로로 바뀝니다.
3. **DWB 지역 계획**
   - 가능한 속도 조합을 미리 굴려 봅니다.
   - 장애물에 닿는 궤적은 버리고, 나머지 중에서 경로를 잘 따르고 목표에 가까워지는 궤적을 고릅니다.
4. **RotationShim** (2026-10-07 추가)
   - 경로가 등 뒤에서 시작하면 DWB가 좌·우 점수가 같아 제자리에서 떠는 문제가 있었습니다.
   - 이제 먼저 경로 방향으로 회전한 뒤 출발합니다.
5. **collision_monitor**
   - 내보내는 속도를 그대로 2초 굴려 봤을 때 로봇 외곽이 장애물에 닿으면, 닿지 않을 만큼 속도를 줄입니다.
6. **복구 행동**: 10초 동안 0.1 m도 못 움직이면 costmap 비우기 → 회전 → 대기 → 후진을 차례로 시도합니다.

### 5-2. 한계·주의
- **라이다 높이 13.2 cm**의 수평면만 봅니다.
  - 이보다 **낮은 물체**(책, 낮은 상자, 케이블)나 **위쪽만 튀어나온 물체**(책상 상판)는 보이지 않습니다.
  - 시연용 장애물은 **20 cm 이상**으로 둡니다.
- 위치 추정(AMCL)이 틀리면 실제 벽이 방 한가운데 장애물로 찍혀 길이 막힙니다. 이때는 웹 **🧭 로봇 위치 지정**으로 위치를 다시 잡습니다.
- 목표 지점 자체를 장애물이 덮으면 그 근처에서 헤매다 실패합니다. "가장 가까운 빈 자리에서 멈추기"는 아직 구현하지 않았습니다.
